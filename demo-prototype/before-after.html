Bob rewrote the supplier-invoice report. Here is what changed.

ZFI_VENDOR_AGING lists unpaid supplier invoices by how overdue they are. It is one of our four made-up test programs. Bob flagged 8 problems in it, then rewrote it for SAP's cloud. Below: what changed, what stayed exactly the same, and what a person still has to decide.

Everything on this page is recorded output from the hackathon runs. Bob's code is shown as written; the trial results come from a free SAP system with stand-in tables, not from a customer's system.

The same rule, side by side

The part of the program a finance person actually cares about: how overdue is "overdue". Bob kept the thresholds and made them testable.

The database read and the file write are gone from this loop; only the rule is left, so it can be tested without any SAP data.

What the seven tests check
7 of 7 passed
  • An invoice due today lands in "0–30".
  • Exactly 30 days overdue is still "0–30".
  • 31 days is the first day of "31–60".
  • Exactly 60 days is still "31–60".
  • 61 days and more is "60+".
  • If no key date is given, today is used.
  • An open item goes through the whole run and comes out with a bucket.

Run on 26 Sep on an SAP BTP trial system, 2.1 seconds. Screenshot of the test panel.

What a person still decides
  • Do the two SAP data views exist, and are they released, on the customer's release?
  • Which channel hands the result to the treasury system?
  • Is a currency conversion actually required? The old comment said yes, the old code said no.
  • Is the log table customer-owned, or governed by an SAP object?
  • How is the job triggered in the cloud: scheduled job, service, or event?

Bob wrote each of these into the code as a candidate note instead of guessing. That is the behaviour the custom mode asks for.
