01 · The problem
31.12.2027

SAP ends mainstream maintenance for ECC 6.0. Companies carry hundreds of custom ABAP programs that break the cloud rules. Each one is reviewed by hand, by the few people who know both worlds.

A project manager's question is not “can AI do this?” but “how well, measured, and where does it fail?”

Clean Core Copilot02
02 · The solution

A Bob custom mode that reviews old SAP code,
and knows what it must not claim.

1 · Bob readsA 12-rule Clean Core catalogue and the program. Read and edit tools only, no system access.
2 · Bob reportsEvery finding with a line range, one rule ID and a reason. Nothing outside the catalogue is invented.
3 · Bob rewritesA data view, a class and unit tests. Every unverified SAP name is marked candidate.
4 · Your system decidesActivation, ATC and tests run on SAP. Bob never claims this step happened.

Mode “Clean Core Architect”: role, 9 custom instructions, rule catalogue and verification rules, all in the public repo.

Clean Core Copilot06
06 · How IBM Bob was used
  • Custom mode “Clean Core Architect”: strict rules, Read + Edit only, no Execute, Browser or MCP.
  • 7 Bob tasks: 4 audits, 1 rewrite, 1 fix after review, 1 parallel run. Every task summary is in bob_sessions/.
  • Parallel sub-agents: three programs, three sub-agents, 13 files in 16 minutes.
  • Asked before every write; for the treasury hand-off it wrote four options and left the choice to a person.
  • 4.258 of 40 Bobcoin for the whole project.

07 · What it means

A strong first reviewer for Clean Core rules.
A weak one for business logic.
The human stays in the loop, and now we know where.

Try it: copy the mode and the catalogue into your Bob workspace, open a legacy .abap file, send one prompt. Browse every finding next to the code on the evidence site.
