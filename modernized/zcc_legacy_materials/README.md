**Legacy:** `SELECT-OPTIONS s_matnr FOR mara-matnr.`

**Modernized:** The selection screen is removed. The method signature

### F-03 CC-01 — `SELECT matnr mtart FROM mara` (lines 15–18)

**Legacy:** Direct `SELECT` on dictionary table `MARA`.
**Rule violated:** CC-01 — no direct access to unreleased SAP tables in ABAP Cloud.

**Modernized:**
- CDS view entity [`I_MaterialByType`](I_MaterialByType.cds) selects from
  `I_Product` *(candidate — verify release on target)*.
- Private method [`select_materials()`](zcl_legacy_materials.abap) issues
  `SELECT … FROM I_MaterialByType` with `IN @it_material_range`.
- Field names `Material` and `MaterialType` are used in both the CDS projection and
  the ABAP structure `ty_material` so that `INTO CORRESPONDING FIELDS` resolves
  without `AS` aliases.

All three names (`I_Product`, `Material`, `MaterialType`) are marked `/* candidate */`.

### F-04 CC-09 — `WRITE: / 'No materials found'` (line 21)

**Legacy:** `WRITE` statement used for list output.
**Rule violated:** CC-09 — no `WRITE`/`ULINE`/`SKIP` in ABAP Cloud.

**Modernized:** The `WRITE` statement is removed. [`run()`](zcl_legacy_materials.abap)
returns the result table (which may be empty) to the caller.
The empty-result guard is preserved as behaviour: if the table is empty the method
returns immediately and the caller decides the reaction (raise an exception, send an
OData error response, log an Application Job message, etc.).

## What a human must still decide

1. **Target product and release.**
   All candidate objects (`I_Product`, field names `Material` and `MaterialType`,
   data types) must be verified against the specific S/4HANA Cloud or on-premise
   release that will host this artefact. The draft verdict below is a hint only and
   must not be treated as authoritative.
   *(draft_verdict_hint: likely feasible on current S/4HANA Cloud Public Edition, unverified)*

2. **`I_Product` — confirm released on target; confirm element names.**
   Verify that `I_Product` is included in the released API surface of the target
   product/release. Confirm that elements named exactly `Material` and `MaterialType`
   exist on `I_Product` and map to `MARA-MATNR` and `MARA-MTART` respectively.
   If the element names differ, update both the CDS projection *and* the ABAP
   `ty_material` structure in the same change (names must match for `CORRESPONDING FIELDS`).

3. **Whether `MARA` has a simplification / compatibility object on the target release.**
   Some releases ship a compatibility view or simplification item for `MARA`.
   If such an object is released and covers the required fields, it may be used as
   an alternative to `I_Product`. Confirm whether it is released, what its API state
   is, and whether it is the preferred access path for the intended scenario.

4. **`REUSE_ALV_GRID_DISPLAY` — confirm deprecated vs. discouraged.**
   Verify whether the function module is formally *deprecated* (with a planned removal
   date) or merely *discouraged* in the target release. The answer affects the urgency
   of replacing F-05 and may influence the migration roadmap for related programmes.

5. **Intended call channel: Fiori UI list report vs. background Application Job.**
   The legacy report was invoked interactively via a selection screen.
   In ABAP Cloud the output and input patterns diverge significantly:
   - *Fiori Elements List Report (OData V4 / RAP):* the CDS view becomes the query
     entity of a RAP Business Object; the `RANGE OF matnr` parameter maps to an OData
     `$filter`; `display_stub()` is not needed.
   - *Application Job (class implementing `IF_APJ_RT_RUN`):* the range is a job
     parameter; output goes to the Application Log or a spool object.
   This decision must precede any further implementation of `display_stub()`.

6. **Authorization objects governing material master data reads.**
   The legacy report relied on the authorization inherited from direct `MARA` access
   (`M_MATE_MAR` / `M_MATE_WRK`, etc.). In the CDS-based model, authorization is
   governed by the access control attached to `I_MaterialByType` (set to `#CHECK`).
   A DCL object and the appropriate authorization objects must be defined and reviewed
   by a security architect before activation.

7. **Whether SELECT-OPTIONS / selection-screen approach must be replaced by OData filter,
   method parameter, or Application Job variant.**
   The current modernization passes a `RANGE OF matnr` parameter, which is a neutral
   intermediate. The final form depends on decision 5 above. If the consumer is an
   OData service, the range should be removed from the ABAP class entirely and the
   filtering expressed in the CDS view's query or in the RAP handler. If the consumer
   is an Application Job, the range is replaced by a typed job-parameter structure.

8. **ABAP object naming alignment.**
   Names `ZCL_LEGACY_MATERIALS`, `ZCL_LEGACY_MATERIALS_TEST`, and
   `I_MATERIALBYTYPE` are placeholders following legacy naming. Align them with the
   target system's namespace reservation and Clean Core naming conventions
   (customer namespace `Z`/`Y`, package assignment, software component) before
   transport creation.
