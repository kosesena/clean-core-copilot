## What changed

One subsection per audit finding from `reports/zsd_open_orders.json`.

### F-01 — `TABLES vbak, vbap, kna1` (CC-10, obsolete)

The `TABLES` statement with implicit work areas is forbidden in ABAP Cloud.
**Resolution:** removed entirely.  All field access is now via typed ABAP structures
(`ty_order`) populated by an ABAP SQL `SELECT … INTO CORRESPONDING FIELDS`.

### F-02 — `OCCURS 0` header-line table (CC-10, obsolete)

`DATA: BEGIN OF … OCCURS 0 … END OF` is an obsolete form of an internal table with
a header line.
**Resolution:** replaced by `TYPES ty_orders TYPE STANDARD TABLE OF ty_order WITH EMPTY KEY`
in [`zcl_open_orders`](zcl_open_orders.abap).

### F-03 — `LIKE vbak-vbeln` etc. (CC-10, obsolete)

`LIKE` references to dictionary fields are not permitted in ABAP Cloud.
**Resolution:** structure components use explicit type names (`vbeln_va`, `erdat`,
`kunnr`, `name1_gp`, `posnr_va`, `matnr`, `kwmeng`, `netwr_ap`).
Field names are marked `/* candidate */` where the ABAP type cannot be confirmed
without the target data dictionary.

### F-04 — `LIKE vbap-netwr` for `w_total` (CC-10, obsolete)

Same as F-03.
**Resolution:** `TotalNetAmount TYPE netwr_ap` in `ty_order`; scalar computed with
`REDUCE` in `apply_sort_and_aggregate`.

### F-05 — `SELECT-OPTIONS` / `PARAMETERS` (CC-10, no GUI in cloud)

Classic selection-screen constructs do not exist in ABAP Cloud.
**Resolution:** the three selection parameters (`s_kunnr`, `s_erdat`, `p_vkorg`) become
explicit importing parameters of `zcl_open_orders=>run()`:
`iv_sales_org TYPE vkorg`, `it_sold_to TYPE RANGE OF kunnr`,
`it_creat_date TYPE RANGE OF erdat`.
Callers (RAP action, Application Job, test) pass ranges directly.

### F-06 — `SELECT` on `VBAK` (CC-01, use released view)

Direct access to the `VBAK` table is not permitted in ABAP Cloud.
**Resolution:** `SELECT` now reads from the CDS view entity `I_OpenSalesOrder`,
which is built on top of `I_SalesDocument` `/* candidate */`.

### F-07 — Three-level nested `SELECT…ENDSELECT` (CC-12, performance)

Nested `SELECT…ENDSELECT` loops issue one SQL statement per outer row,
causing N+M+K round trips.
**Resolution:** a single flat `SELECT` against the joined CDS view replaces all
three loops.  The join between sales document, item, and customer is pushed
to the database layer inside `I_OpenSalesOrder`.

### F-08 — `SELECT` on `VBAP` (CC-01, use released view)

Direct access to `VBAP` is not permitted in ABAP Cloud.
**Resolution:** item fields come from `I_SalesDocumentItem` `/* candidate */`
joined inside `I_OpenSalesOrder`.

### F-09 — `SELECT SINGLE` on `VBUP` for delivery status (CC-01, view unknown)

No confirmed released CDS view covering `VBUP-LFSTA` exists at the time of writing.
**Resolution:** the filter `DeliveryStatus <> 'C'` is placed in the CDS view
`WHERE` clause as a `/* candidate */` reference.  A delivery-status join stub is
left as a clearly labelled comment block in `I_OpenSalesOrder.cds`.
See [§ What a human must still decide](#what-a-human-must-still-decide), item 3.

### F-10 — `SELECT SINGLE name1 FROM kna1` (CC-01, use released view)

Direct access to `KNA1` is not permitted in ABAP Cloud.
**Resolution:** `I_Customer` `/* candidate */` is joined in the CDS view, exposing
`CustomerName` `/* candidate */`.

### F-11 — `MOVE-CORRESPONDING` (CC-10, obsolete)

`MOVE-CORRESPONDING` is obsolete.
**Resolution:** data is moved implicitly via `SELECT … INTO CORRESPONDING FIELDS OF TABLE`,
relying on the CamelCase field names in `ty_order` matching the CDS element names exactly.

### F-12 — `FORM get_data` subroutine (CC-11, obsolete)

Subroutines (`FORM`/`ENDFORM`) are forbidden in ABAP Cloud.
**Resolution:** logic moved to the private method `select_open_orders` and the
public method `run` in `zcl_open_orders`.

### F-13 — `FORM print_list` subroutine (CC-11, obsolete)

Same as F-12.
**Resolution:** sort and aggregate logic moved to `apply_sort_and_aggregate`;
output replaced by `display_stub`.

### F-14 — `PERFORM` calls (CC-11, obsolete)

`PERFORM` is forbidden in ABAP Cloud.
**Resolution:** replaced by method calls within `run()`.

### F-15 — `WRITE` / `ULINE` list output (CC-09, no list processing)

Classic list processing (`WRITE`, `ULINE`, `SKIP`) is not available in ABAP Cloud.
**Resolution:** replaced by `display_stub()` with a `TODO` comment instructing
the developer to implement an OData V4 / Fiori Elements List Report or an
Application Job output channel.

### F-16 — `AT NEW` / `ENDAT` control break (CC-09, no list processing)

`AT NEW … ENDAT` is a classic list-processing construct, not available in ABAP Cloud.
**Resolution:** grouping logic is no longer needed; the sorted result table returned
by `run()` carries all data.  Customer-name headers are a UI-layer concern
(Fiori Table grouping).

### F-17 — `ADD … TO` (CC-10, obsolete arithmetic)

`ADD x TO y` is an obsolete arithmetic statement.
**Resolution:** replaced by `REDUCE netwr_ap( INIT s … NEXT s = s + row-NetAmount )`
in `apply_sort_and_aggregate`.

### F-18 — Hard-coded `LFSTA 'C'` / misleading comment (Unclassified)

The legacy comment *"open = no delivery yet"* was imprecise; `'C'` actually means
*fully delivered*, not *no delivery*.  The filter excluded `'C'` items, i.e.
it kept not-yet-delivered **and** partially delivered items.
**Resolution:** the filter is preserved as `DeliveryStatus <> 'C'` in the CDS
`WHERE` clause with a corrected inline comment.  The business rule is also
documented as a specification-assertion test (`delivery_status_c_literal`) in
`zcl_open_orders_test`.
A human must decide whether partially delivered items (`'B'`) should also be
excluded — see [§ What a human must still decide](#what-a-human-must-still-decide), item 5.

## What a human must still decide

1. **Target product and release.**  
   Confirm the SAP S/4HANA on-premise or BTP ABAP Environment release.  Some
   released CDS views and type names differ between releases.  No assumption was made.

2. **`I_SalesDocument` and `I_SalesDocumentItem` release contract and field coverage.**  
   Verify that both views exist, are released for customer use in the target release,
   and expose all required fields with the exact element names used in
   `I_OpenSalesOrder.cds` and `ty_order` (`SalesDocument`, `CreationDate`,
   `SoldToParty`, `SalesDocumentItem`, `Material`, `OrderQuantity`, `NetAmount`,
   `SalesOrganization`).  Adjust `/* candidate */` fields and types accordingly.

3. **Released CDS view for `VBUP-LFSTA` delivery status — the biggest unknown.**  
   No released CDS view covering the `VBUP` item-delivery status table was confirmed
   at the time of writing.  Candidates to investigate:
   - `I_SalesDocumentItemDeliveryStatus` (if it exists in the target release)
   - `I_SalesOrderItemScheduleLineDelivery`  
   - Fields on `I_SalesDocumentItem` itself (some releases embed selected VBUP fields)  
   Once the correct view/field is identified, replace the stub comment in
   `I_OpenSalesOrder.cds` with a real join/association and update the `WHERE` clause.

4. **`I_Customer` release status and `CustomerName` field name.**  
   Verify that `I_Customer` is released for the target release and that the field
   carrying `KNA1-NAME1` is named `CustomerName`.  If the view is `I_BusinessPartner`
   or the field is `OrganizationBPName1`, update the CDS join and `ty_order` component
   accordingly.  Remove `/* candidate */` annotations once verified.

5. **Delivery-status business rule: exclude only `'C'` (fully delivered) or also `'B'` (partially delivered)?**  
   The legacy code kept `'B'` (partial delivery) items in the open-order list.
   Confirm with the business owner whether this is intentional.  If partially
   delivered items should also be excluded, extend the CDS `WHERE` clause to
   `DeliveryStatus NOT IN ('B', 'C')` and update `delivery_status_c_literal` test.

6. **Output channel: Fiori Elements List Report vs. background Application Job.**  
   Replace `display_stub()` with the agreed output mechanism:
   - **Fiori Elements List Report** — expose `I_OpenSalesOrder` (or a projection)
     as an OData V4 service; the class becomes a RAP behaviour or action handler.
   - **Application Job** — use `CL_BALI_LOG` / `CL_APPL_LOG` APIs to write the
     sorted table to an application log and schedule via `CL_APPL_JOB_*`.

7. **Authorization objects for sales order and customer data.**  
   Define which authorization objects protect the CDS view
   (`@AccessControl.authorizationCheck: #CHECK` is set, but the DCL artefact and
   the backing authorization objects (`V_VBAK_VKO`, `V_KNA1_BRG`, etc.) must be
   created or mapped to the new view).

8. **ABAP object naming alignment.**  
   Confirm the customer namespace prefix (currently `Z`) and naming conventions
   on the target system.  Rename `I_OpenSalesOrder`, `zcl_open_orders`,
   `zcl_open_orders_test` if the project uses a different prefix
   (e.g., `YY1_`, a registered namespace `/CUST/`).
